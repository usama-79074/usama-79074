# 🧩 Backend Architecture

I like keeping backend projects organized instead of putting everything into one file.

A typical architecture I work toward looks like:

```text
app/
│
├── core/
│   ├── config
│   └── security
│
├── database/
│   ├── connection
│   └── session
│
├── models/
│   └── database_models
│
├── schemas/
│   └── pydantic_schemas
│
├── routers/
│   └── api_routes
│
├── services/
│   └── business_logic
│
└── utils/
    └── helper_functions
```

This approach helps keep applications:

* Clean
* Maintainable
* Scalable
* Easier to debug
* Easier to extend
